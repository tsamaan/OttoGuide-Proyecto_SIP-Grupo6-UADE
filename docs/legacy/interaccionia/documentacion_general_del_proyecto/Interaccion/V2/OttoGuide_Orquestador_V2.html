main_v2.py
Orquestador async

Reescritura asíncrona del orquestador de conversación de Ottoman. Arquitectura asyncio pura con aiohttp para HTTP y asyncio.create_subprocess_exec para procesos. Preparado para integración con el SDK nativo de Unitree.

asyncio + aiohttp Whisper Docker Gemma4 otto OTTO_ENV dual-mode TTS
Evolución

V1 → V2 · Qué cambió

main_v2.py mantiene el mismo pipeline y lógica conversacional de V1 pero reescrito en async puro. No modifica ni rompe main.py que sigue funcionando en paralelo.

Componente V1 — main.py V2 — main_v2.py
Modelo de ejecución Síncrono — llamadas bloqueantes Async — asyncio.run(main())
HTTP (Whisper + Ollama) requests.post() bloqueante aiohttp.ClientSession compartida async
Subprocesos (arecord, docker, paplay) subprocess.run() bloqueante asyncio.create_subprocess_exec() async
Backend TTS Siempre Piper Docker Dual-mode via OTTO_ENV: Docker (notebook) / SDK (robot)
Detección fin de audio esperar_fin_audio() síncrona con time.sleep() esperar_fin_audio() async con asyncio.sleep()
Sesión HTTP Nueva conexión por cada request Sesión aiohttp compartida para toda la ejecución
SDK Unitree No contemplado hablar_sdk() preparado — fallback a Docker hasta validar
✓ Compatibilidad total. main_v2.py y main.py pueden coexistir en services/core/ sin interferirse. No comparten estado ni archivos de lock.
API interna

Funciones del orquestador

Todas las funciones son async. Se organizan en capas: utilidades, audio, STT, LLM y TTS.

utilidades
limpiar(texto) · formatear_para_tts(texto) · similar_a_uade(palabra)
corregir_transcripcion(texto) · calcular_timeout(pregunta)
Funciones síncronas de procesamiento de texto. Idénticas a V1 — eliminan emojis, agregan pausas naturales, corrigen variaciones fonéticas de UADE via Levenshtein y calculan timeout HTTP según longitud de pregunta.
audio
async grabar(duracion, path)
asyncio.create_subprocess_exec("arecord", ...)
Graba N segundos de audio del micrófono de forma no bloqueante. await proc.wait() espera el fin de la grabación sin bloquear el event loop. Usa MIC_DEVICE y MIC_CHANNELS configurados arriba.
STT
async transcribir(path, session)
aiohttp.FormData + session.post(STT_URL)
Verifica amplitud del WAV, manda a Whisper HTTP via aiohttp, filtra falsos positivos de Whisper y corrige UADE con Levenshtein. La session se reutiliza entre llamadas para eficiencia de conexión.
LLM
async preguntar_llm(pregunta, session)
session.post(LLM_URL, json={model: "otto", ...})
Envía la pregunta al modelo otto en Ollama via aiohttp. Sin num_predict — el Modelfile controla la longitud. Timeout dinámico calculado por calcular_timeout(). Retorna la respuesta formateada para TTS.
TTS
async hablar_docker(texto)
docker cp + docker exec piper + paplay · Popen async
Escribe el texto a /tmp/otto_texto.txt (UTF-8 para preservar acentos), copia al contenedor ottoguide-tts, genera WAV con Piper, copia de vuelta y reproduce con paplay. Usa esperar_fin_audio() async para detectar fin real del audio antes de activar el micrófono.
TTS · SDK TODO
async hablar_sdk(texto)
AudioClient.TtsMaker(texto, speaker_id=0)
TTS via SDK nativo de Unitree. Activo cuando OTTO_ENV=robot. Actualmente con fallback a hablar_docker() hasta validar soporte de español, latencia y calidad en el robot físico. Completar con la implementación del SDK cuando se confirme en hardware.
orquestador
async main()
asyncio.run(main())
Loop principal. Crea una aiohttp.ClientSession compartida para toda la ejecución. Loop externo de hibernación (wake word en ciclos de 3s). Loop interno de conversación (preguntas hasta despedida). asyncio.run(main()) como entry point con KeyboardInterrupt para salida limpia.
Configuración

Variable OTTO_ENV

Controla qué backend TTS usa el orquestador. Sin cambiar código, solo cambiando la variable de entorno.

OTTO_ENV=notebook (default)
Usa hablar_docker() — TTS via contenedor ottoguide-tts con Piper. Requiere Docker corriendo con docker compose up -d.

Voz activa: es_MX-gevy-high.onnx
Audio: paplay + PipeWire
OTTO_ENV=robot
Usa hablar_sdk() — TTS via SDK Unitree AudioClient.TtsMaker(). Actualmente fallback a Docker hasta validar en hardware real.

Requiere: SDK instalado, CycloneDDS, firmware v1.3.0
Pendiente: validar español, latencia, volumen

# Notebook (desarrollo) — usa Docker TTS python3 services/core/main_v2.py # Robot Jetson — usa SDK AudioClient (con fallback a Docker) OTTO_ENV=robot python3 services/core/main_v2.py
